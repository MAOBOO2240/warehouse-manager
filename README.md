# 倉儲管理系統

Windows 單一免安裝 `.exe`，100% 本機離線運行，資料以 JSON 存在 `.exe` 旁的 `projects/` 資料夾。
技術：Tauri 2（Rust）＋ Vue 3 ＋ Vite ＋ Pinia ＋ Tailwind CSS 4。

---

## 一、取得 WarehouseManager.exe

**直接下載**：到本 repository 的 [Releases](../../releases) 頁面，下載 v1.0.0 附件中的 `WarehouseManager.exe` 即可使用。

**自動更新**：程式開啟時會自動檢查 GitHub 上有沒有新版本（之後每 3 小時再檢查一次）。「自動更新」預設是開的：剛開啟程式時發現新版本，會顯示「5 秒後自動更新」的倒數（這時可以按「稍後」），時間到就自動下載、替換程式並重新開啟，`projects/` 裡的資料不會動到。使用到一半才發現的新版本只會跳出「有新版本」提醒，不會自己重新開啟；按「稍後」則等下次開啟，左下角齒輪會多一個小藍點。左下角齒輪「設定」→「版本」可以關掉自動更新（改成每次先詢問）、手動「檢查更新」，並看得到上次檢查的時間與結果——查不到新版本時會直接寫出原因。版本號固定 1.0.0，以編譯編號（例如「編譯 #12」）區分新舊；下載的新版本會先和 GitHub 編譯時算好的 SHA-256 比對，不一樣就不更新。

> **倉庫是私人（Private）的時候，一定要設定更新權杖，否則程式查不到新版本。**（沒登入查私人倉庫，GitHub 一律回「找不到」。）
>
> 1. GitHub 右上角頭像 → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token。
>    Repository access 選 **Only select repositories** → 只勾這個倉庫；Permissions → Repository permissions → **Contents：Read-only**（其他都不要給）；期限選越長越好。
> 2. 這個倉庫 → Settings → Secrets and variables → Actions → New repository secret，名稱填 `UPDATE_TOKEN`，內容貼上剛剛的權杖。
> 3. Actions →「Build Windows EXE」→「Run workflow」重新編譯。執行結果的摘要會顯示「更新權杖：已設定」與「檢查通過：已安裝的程式查得到這個版本」。
> 4. **第一次要手動換檔**：現在各台電腦上的舊版沒有權杖、查不到新版本，請把新的 `WarehouseManager.exe` 複製過去覆蓋一次；之後就會自己更新。
>
> 注意：權杖是編譯時包進 exe 裡的（打散存放，不是加密），拿到 exe 的人有辦法取出來讀這個倉庫的原始碼，所以只給「這個倉庫、唯讀」。權杖快到期時要先換新的再讓舊的失效：產生新權杖 → 更新 `UPDATE_TOKEN` → 重新編譯（Actions →「Build Windows EXE」→「Run workflow」；程式碼沒有改也沒關係，重新編譯出來的版本各台電腦一樣會當成新版本自動更新）→ 等各台電腦都更新完 → 才刪掉舊權杖；舊權杖先過期的話，那些電腦就要再手動換一次檔。
> 不想管權杖的話，把倉庫改成 Public 就不需要設定任何東西（權杖過期之後才改成 Public 也可以：程式發現權杖失效時會改用不帶權杖的方式再查一次）。

### 用 GitHub 自動打包（不必在電腦上裝開發工具）

1. 到 GitHub 建立一個新的 repository（建議設為 Private）。
2. 把本資料夾的所有檔案上傳到該 repository（網頁上「Add file → Upload files」直接拖曳整個資料夾即可，
   注意 `.github` 資料夾也要一起上傳）。
3. 上傳後打開 repository 的 **Actions** 分頁，會看到「Build Windows EXE」開始執行（約 5–15 分鐘）。
   若沒有自動執行，點進「Build Windows EXE」→「Run workflow」。
4. 執行完成（綠色勾勾）後點進該次執行，頁面最下方 **Artifacts** 區的 `WarehouseManager-windows`
   就是打包好的檔案，下載解壓縮即得到 `WarehouseManager.exe`。
5. 每次推送到 main（程式檔有改動時），編譯成功後會自動覆蓋發布 Releases 的 `v1.0.0`（附上 `WarehouseManager.exe` 和驗證用的 `WarehouseManager.sha256`），已經在用的電腦開啟程式時就會收到更新。
   想重新編譯發布一次：Actions →「Build Windows EXE」→「Run workflow」。
6. 也可以只上傳一個 `source.tar.xz` 原始碼壓縮檔：「Unpack source」流程會自動解開、提交並接著執行打包。
   `.github/workflows` 裡的流程檔不會從壓縮檔更新（GitHub 不允許自動流程修改流程檔），要改流程檔請直接在網頁上編輯或上傳。
   **流程檔有更新的那一次**（例如這一版加了更新權杖與編譯代號）：把 `.github/workflows` 裡的兩個檔案和 `source.tar.xz` 一起上傳（同一次提交），
   或先上傳流程檔、再上傳 `source.tar.xz`。順序反過來的話：壓縮檔裡有 `.github` 時，那一次的「Unpack source」會直接失敗（GitHub 拒絕自動流程修改流程檔）；
   沒有 `.github` 時會用舊流程編譯，編出來的程式不帶更新權杖。補救：先把兩個流程檔上傳，再到 Actions →「Build Windows EXE」→「Run workflow」重新編譯一次。

流程中會先執行 Rust 單元測試（原子寫入、備份輪轉與還原、負庫存阻擋、斷電後交易補完、移除存放地點、ZIP 匯入匯出、清除暫存檔不動到資料、排列順序檔驗證、更新權杖還原），測試失敗就不會產出 exe。

### 也可以在自己的 Windows 電腦編譯

需要：Node.js 20 以上、Rust（rustup）、Visual Studio Build Tools（勾選「使用 C++ 的桌面開發」）。

```powershell
pip install pillow
python scripts/make_icons.py     # 產生程式圖示（只需執行一次）
npm install
npm run tauri dev                # 開發模式（會開啟視窗，修改程式即時更新）
npx tauri build --no-bundle      # 產出 src-tauri\target\release\warehouse-manager.exe
cargo test --manifest-path src-tauri/Cargo.toml   # 執行 Rust 單元測試（需先 npm run build）
```

只想看畫面、不想裝 Rust 的話：`npm install` 後執行 `npm run dev`，用瀏覽器開 `http://localhost:5173/dev/preview.html`。
這一頁用記憶體裡的假後端（`dev/mock-backend.js`，內含示範資料）跑同一套前端，不會讀寫任何真正的資料檔；網址加 `?reset` 重新產生示範資料、`?empty` 從空白專案開始、`?update=1` 模擬有新版本。`dev/` 不會被打包進正式版。

## 二、使用前須知

* **放置位置**：請把 exe 放在可寫入的資料夾，例如桌面、`D:\倉儲\`、隨身碟。
  不要放在 `C:\Program Files`（Windows 不允許一般程式在那裡寫檔，程式會提示無法啟動）。
* **WebView2**：Windows 11 與絕大多數 Windows 10 已內建。若開啟後一片空白或提示缺少元件，
  到微軟官網下載安裝「Microsoft Edge WebView2 Runtime（Evergreen）」即可。
* **搬移到別台電腦**：把 exe 與 `projects` 資料夾一起複製過去，或在舊電腦按「匯出備份 (ZIP)」，到新電腦按「匯入備份 (ZIP)」選擇該檔即可（匯入會建立新專案，不會覆蓋既有專案）。
* **不要用 Excel 直接開啟 JSON 檔**：檔案被鎖住時程式會提示「檔案正被其他程式使用」。需要報表請用畫面上的「匯出 CSV」。

## 三、功能一覽

| 模組 | 說明 |
|---|---|
| 專案管理 | 頂部專案選單（彈出清單，目前專案打勾）切換多個倉庫專案；同一個選單下方有新增專案、匯入備份、匯出這個專案的備份、刪除專案（放在最下面，刪除前二次確認，資料夾移到 `projects\_已刪除專案` 可救回）；匯入時建立為新專案，名稱重複自動加上「(2)」 |
| 主頁面 | 一眼看懂的總覽：在庫總件數、存放地點數、今日入庫、今日出貨／損壞四張數字卡；「近 14 天進出」長條圖（入庫往上、出貨與損壞往下，可切換成表格）；「各存放地點的庫存」與「庫存最多的品項」排行長條（點地點直接看該地點的庫存）；最近 8 筆異動 |
| 入庫 | 點品項欄列出所有品項（可捲動），或直接輸入新名稱「新增品項」；選好後點品項卡即可更換；存放地點預設空白、可不填，點欄位會列出已使用過的地點；數量自動帶入該品項第一次入庫的數量。**改變地點也在這裡**：已有庫存的品項可以把「入庫方式」切成「改變地點」，選從哪裡移出、移到哪裡（數量預設帶入該地點的全部），總數不變、歷史紀錄記一出一入；要移到哪裡一定要自己選——輸入或選擇一個地點，或點「未指定（不設定地點）」，欄位留空不能送出，庫存不會不小心被移到「未指定」 |
| 出庫/損壞 | 選品項（點品項卡可更換）→ 存放地點：專案裡從沒填過存放地點時整段不顯示（入庫、出庫畫面和訊息也不會出現「未指定」），選好品項就直接確認數量；有用存放地點時，只放在一個地點的品項自動選好，放在好幾個地點時點選要從哪裡出庫（顯示各地點現量）→ 動作「出貨」或「損壞」；損壞需選原因：道具受損／印刷錯誤／其他（自行輸入）；數量超過現量時按鈕停用並顯示紅字，Rust 端再次校驗 |
| 庫存清單 | 兩種顯示方式（上方切換，會記住）：**「依地點」**——每個存放地點各自一區（地點名稱、幾項、幾件），區內每列是放在那裡的品項，「數量」是這個地點的數量，旁邊的「總數」是這個品項不分地點的合計；**「品項總數」**——每個品項一列，顯示總數，並把各地點的數量直接列成標籤（不用把滑鼠移上去）。左側選單「庫存清單」底下仍會列出各地點，點某地點只看該地點。每列的「操作」是「入庫／出庫／損壞」，要改變地點請按「入庫」→「改變地點」。**移除存放地點**：每個地點區塊右上角的「移除地點」，選擇那裡的庫存要改放到「未指定」或其他地點，一次全部移過去（數量不變、歷史紀錄每個品項記一出一入、註記與排列順序跟著搬），之後這個地點不再出現在清單與選單；頁面最下方另外列出「沒有庫存的存放地點」，用不到的名稱也可以移除。完全沒有填地點的專案不顯示任何地點相關的欄位。「註記」欄點一下即可編輯；畫面太窄時先收起「最後異動」欄；按住列左側六點圖示（或長按該列）可在同一區內拖曳排序，順序存在 row_order.json，「恢復名稱排序」可還原；可匯出 CSV（每個地點一列，最後多一欄「總數（不分地點）」） |
| 歷史紀錄 | 依類型（入庫／出貨／損壞／移動地點，彈出式選單）、起訖日期（年月日自動跳格＋彈窗日曆）、品項或地點篩選；篩選結果上方有入庫／出貨／損壞／移動地點的合計；紀錄依日期分組，品項與存放地點、原因與備註各自合成一欄，不用左右捲動；可匯出 CSV（UTF-8 BOM，Excel 開啟不亂碼） |

* 入庫、出庫與庫存清單快速操作的數量欄位都可輸入算式：`+ - × ÷`（也可用 `* / x`）與括號，例如 `12*5+3`，欄位下方即時顯示「= 63 件」；結果必須是大於 0 的整數。
* 品項不需預先建檔；第一次入庫的數量會記在品項上（`first_qty`），之後入庫、出庫選到該品項時自動帶入，仍可修改；出庫、損壞時帶入的數量不會超過該地點現有的數量。
* 存放地點為自由輸入，不需預先設定；空白會顯示為「未指定」。使用過的地點會出現在欄位的彈出清單中（可邊打字邊篩選）；被移除的地點不會再出現，之後再用同一個名稱入庫就會自動回來。
* 所有下拉選單與輸入建議都是程式內的彈出清單，外觀與專案選單一致；瀏覽器記憶的輸入紀錄已關閉。
* 介面為圓潤氣泡風格：懸浮卡片＋膠囊按鈕，卡片圓角使用 G2 連續曲率（CSS `corner-shape: squircle`，需 WebView2 139 以上）。每一頁的標題前有該頁的圖示，顏色和左側選單一致（入庫綠、出庫藍、損壞紅、存放地點紫）。
* 外觀：**深色是「石墨灰」**——視窗底色是 `#8A8B8A`，卡片、側邊欄與選單是同色系的炭灰，文字與按鈕的對比都重新算過（卡片上的文字 5.9:1 以上；實心按鈕一律亮色底配深色字）；視窗標題列會跟著深色／淺色切換。另有淺色外觀。
* 左下角齒輪「設定」：文字大小（大／中／小）與深色／淺色外觀，設定會記住；「清除緩存」會刪除殘留的暫存檔（.tmp、中斷的匯入暫存資料夾）並清除畫面快取後重新載入，不會動到任何資料、.bak 備份與設定；「版本」顯示目前的編譯編號、上次檢查更新的結果，可以按「檢查更新」、開關「自動更新」。

## 四、資料安全設計

```
WarehouseManager.exe
projects/
├── _app_state.json        記錄上次開啟的專案
└── 預設總倉/
    ├── config.json  products.json  locations.json  inventory.json  logs.json
    ├── remarks.json       庫存清單的註記
    ├── row_order.json     庫存清單的自訂排列順序
    ├── pending_tx.json    交易日誌（僅在寫入中途存在）
    └── backups/           每個檔案各保留最新 5 份 .bak
```

* **原子寫入**：舊檔備份到 `backups/` → 新內容寫入 `.tmp` 並 `sync_all()` → `rename` 覆蓋正本。
  任何時間點斷電，正本只會是完整舊版或完整新版，不會變成 0 位元組。
* **寫入佇列**：Rust 端所有檔案操作排隊依序執行，快速連點不會互相衝突。
* **交易一致性**：每筆庫存異動先寫入 `pending_tx.json`（交易日誌），再依序更新 `logs.json`、`inventory.json`。
  若中途斷電，下次開啟專案會自動補完，庫存與歷史紀錄保持一致。
* **移除存放地點也是一筆交易**：那個地點的庫存全部移到指定的地點（或「未指定」），不會刪掉任何庫存；
  同一筆交易日誌裡一併更新 `config.json`（`removed_locations` 記下移除時間）、`remarks.json` 與 `row_order.json`（註記與排列順序跟著搬），斷電一樣會補完。
  歷史紀錄不會被改寫——舊紀錄仍然寫著原本的地點名稱，只是選單裡不再出現。
* **負庫存**：前端即時阻擋；後端計算後若任何存放地點會小於 0，整筆交易中止、不寫入任何檔案與日誌。
* **庫存與歷史紀錄只能經由作業功能異動**：通用寫入 API 只接受設定、品項、地點、註記與排列順序檔，且寫入前會檢查格式。
* **損壞偵測與還原**：開啟專案時若有檔案損壞或被鎖定，系統進入唯讀並詢問
  「是否從最近一次 .bak 備份還原？」。還原時會略過同樣損壞的備份，原本損壞的檔案另存為 `*_corrupt_*.json`。

## 五、乾淨電腦驗收步驟

1. 在未安裝 Node.js／Rust 的 Windows 10/11 電腦，把 `WarehouseManager.exe` 放到桌面新資料夾，雙擊開啟。
2. 確認 exe 旁自動出現 `projects\預設總倉\`，內含 JSON 資料檔與 `backups\`。
3. 入庫：品項欄輸入「測試海報」→ 選「新增品項」→ 存放地點留空 → 數量 50 → 確認入庫。
4. 再次入庫選「測試海報」：數量應自動帶入 50。
5. 出庫/損壞：選「測試海報」→ 不用選存放地點（還沒填過地點），數量應自動帶入 50 → 改成 60：按鈕停用並顯示「庫存不足！目前只剩 50 件，不可出貨 60 件」。
6. 動作選「出貨」出 10 件；再選「損壞」→「其他」→ 輸入原因 → 登記 2 件。歷史紀錄應有入庫、出貨、損壞各一筆。
7. 匯出庫存清單與歷史紀錄 CSV，用 Excel 開啟確認中文正常。
8. 庫存清單：按「測試海報」那列的「入庫」→ 切到「改變地點」→ 移到「A 櫃」、數量改成 5 → 確認移動。畫面上方出現「依地點／品項總數」切換；「依地點」有「A 櫃」（5 件）和「未指定」兩區，兩區的「總數」欄是同一個數字（兩個地點加起來）；切到「品項總數」只有一列，顯示總數，後面列出「A 櫃」「未指定」兩個標籤和各自的數量。左側「庫存清單」底下出現「A 櫃」和「未指定」，點「A 櫃」只顯示該地點。
9. 移除存放地點：在「A 櫃」那一區按「移除地點」→ 保持「未指定」→ 移除地點。「A 櫃」消失、測試海報全部回到「未指定」，總數不變；歷史紀錄多出一出一入兩筆「移動地點」；入庫頁的存放地點清單裡不再有「A 櫃」。
10. 設定：切換深色／淺色，視窗標題列跟著變；「自動更新」開關可以切換；按「檢查更新」會顯示結果（查不到時會寫出原因）。
